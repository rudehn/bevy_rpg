# Chasms

Chasms are void tiles that drop the player to the next floor with fall damage. They appear as dark gaps in the dungeon floor, generated by the lake builder alongside water and lava.

## Mechanics

### Player Falls

When the player attempts to move into a chasm tile:
1. A confirmation dialog appears: "A gaping chasm yawns before you. Fall to the next floor? (2d6 damage)"
2. **Enter** confirms: player takes 2d6 fall damage, floor transition triggers, player lands on a random safe walkable tile on the next floor
3. **Esc** cancels: no movement, no turn cost
4. Fall damage is applied BEFORE the floor transition (player could die from the fall)
5. If the player dies from fall damage, game over triggers normally (no floor transition)

### Floor Transition

Chasm falls use the same floor transition system as stairs:
- Current floor is cached (same as descending stairs)
- Next floor is generated or restored from cache
- Player spawns at a random walkable tile (not the stair position)
- `StairCooldown` applied to prevent immediate re-trigger

### Items

- Drifting items that enter a chasm tile are destroyed (despawned)
- Log message: "The [item name] falls into the chasm!"
- Items on chasm tiles at floor load are also destroyed (cleanup)

### Monsters

- Chasms are **impassable** for monster pathfinding (return `None`, same as walls)
- Monsters never voluntarily enter chasms
- Knockback into a chasm: monster is destroyed (falls to death)

### Generation

- Lake builder generates chasms at all floor depths (1-26)
- Depth-based probability updated to include chasms:
  - Depths 1-5: 70% Water, 15% Lava, 15% Chasm
  - Depths 6-26: 40% Water, 35% Lava, 25% Chasm
- Chasms have no wreath (no shallow edge decoration)
- Chasm lakes validated for connectivity (same as water/lava)

### Rendering

- ASCII: space character on dark background `#0A0A14`
- Chasm tiles are not opaque (player can see across them)
- Chasm tiles block FOV: no (transparent void)

## Implementation

### New State: `InGameState::ChasmConfirm`

Stores the pending chasm target position. Modal displays confirmation prompt.

### Movement Integration

`resolve_bump()` in `actions.rs` returns a new `BumpResult::Chasm(Position)` when the target tile has `LiquidType::Chasm`. The movement handler opens the confirmation dialog instead of moving.

### Pathfinding

`is_pathing_blocker()` already returns true for chasms. Change pathfinding to return `None` (impassable) instead of `Some(5.0)` for chasm tiles, making them walls for AI.

### Item Drift

`item_drift_system` in `water.rs`: when choosing a random neighbor, if the chosen tile is a chasm, despawn the item and log the message.
